# CQ, MF, and Luna-style contract map

| Contract | Implementation |
|---|---|
| CQ-01 | Approved raw-byte source candidates, exact occurrence enumeration, optional Git identity, unique/ambiguous/no-match, mutation invalidation |
| CQ-02 | Typed Vitest/Jest and Node/V8 reports with conservative fallback |
| CQ-03 | Explicit failure/source/type/config/runtime/external evidence obligations and bounded retrieval |
| CQ-04 | Exact and CI-scoped repetition reduction with content-addressed restoration |
| CQ-05 | Tree-sitter JS/TS units, TypeScript semantic edges, `DeliveryRules`, and `buildDeliveryPlan` |
| CQ-06 | Satisfied/missing/ambiguous/contradicted/stale sufficiency and Gather More Evidence precedence |
| CQ-07 | Captured/current/both/cancel/editable merge and digest-bound review approval |
| MF-01 | Exact-operation hard filters and current-model retention |
| MF-02 | Bounded-routine eligibility and deterministic cost/latency score |
| MF-03 | Reasoning-capability hard filter and reasoning-intensive score |
| Luna-style | External-root JSON protocol adapter plus read-only prompt pass-through integrity; live execution is reported separately |

The Rohit CQ/MF and Luna adapters are external protocol bridges. They never
vendor private fixtures or implementation code.
